# MK Sensors

Система мониторинга объектов на FastAPI, PostgreSQL, Vue 3, PrimeVue 4, Pinia, Vue Router и MapLibre GL JS.

## Что включено

- регистрация, вход и профиль пользователя;
- JWT-аутентификация и ролевая модель доступа;
- управление пользователями, ролями и разрешениями;
- карта объектов, справочник объектов и журнал показаний;
- территориальные назначения объектов;
- адаптивный layout и светлая/тёмная тема.

Добавлена основа `mk_sensors`: объекты, каналы, события и RBAC с областями
доступа по подразделениям, районам и назначениям объектов. Роли: диспетчер,
техник, руководитель и отдельный администратор. Настройка и API описаны в
[RBAC_SPEC.md](docs/RBAC_SPEC.md).

Новые предметные модули добавляются через отдельные модели, API-router,
Pinia store и Vue-view.

## Быстрый запуск

```bash
cp .env.example .env
# замените SECRET_KEY и параметры PostgreSQL
uv sync
uv run alembic upgrade head
uv run uvicorn main:app --reload --port 8000
```

Во втором терминале:

```bash
cd frontend
cp .env.example .env.development
npm ci
npm run dev
```

Frontend откроется на `http://localhost:5173`, API — на `http://localhost:8000/api`.

## Прогноз неисправности

Авторизованный диспетчер может сохранить новое показание и сразу запустить
подходящую модель через `POST /api/forecasts`:

```json
{
  "channel_id": 8812,
  "event_at": "2026-09-23T14:30:00+03:00",
  "is_alarm": false,
  "sensor_value": "Исправен"
}
```

Модель выбирается по идентификатору канала. Показание сохраняется в `events`,
а результат — в `forecasts`. Журнал доступных пользователю прогнозов возвращает
`GET /api/forecasts`. Прогноз относится к состоянию «Неисправен» в окне от 1 до
31 дня после даты показания; при недостаточной истории API возвращает отдельный
статус вместо искусственного отрицательного результата. Для канала, которого нет
в справочниках моделей, показание всё равно сохраняется, а журнал получает запись
со статусом `unsupported_channel` и без выдуманной вероятности.

## Первый администратор

После регистрации назначьте пользователю роль `admin`:

```bash
uv run python scripts/promote_user.py admin@example.com
```

Шаблон не создаёт администратора с паролем по умолчанию.

## Тестовые пользователи

После заполнения территорий можно создать штат тестовых пользователей:

```bash
uv run python scripts/seed_users.py \
  --domain example.com \
  --password 'ChangeMe123!'
```

Скрипт создаёт одного диспетчера для каждой из четырёх диспетчерских, по три
техника для каждой из восьми служб эксплуатации, одного администратора и одного
руководителя. Администратор и руководитель прикрепляются ко всем подразделениям. Повторный запуск
обновляет роли и подразделения без дублирования пользователей. Пароли существующих
seed-пользователей сохраняются; для их замены добавьте `--reset-passwords`.

Регистрация не ограничена доменом `mos.ru`: принимается любой синтаксически
корректный email. Параметр `--domain` управляет только адресами seed-пользователей.
